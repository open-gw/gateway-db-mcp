# Total payloads: 47
# Blocked at Layer 4 (QueryValidator): 41  — 87%
# Expected failures (marked [BYPASS-L4]): 6  — blocked by Layer 1 (read-only DB user)
#
# The 6 [BYPASS-L4] payloads represent known heuristic limitations:
#   - MySQL conditional comments (not stripped by standard block-comment pattern)
#   - Inline comment used to split keyword across tokens
#   - Percent-encoded keyword decoded upstream of the bridge (not by the validator)
#   - Vendor-specific HANDLER syntax outside the denylist
#   - MySQL file-read function — passes SELECT-prefix rule; blocked by L1 (no FILE privilege)
# All 6 are stopped by Layer 1 (mandatory read-only database credential) in any
# correctly provisioned production deployment.
#
# Threat-model note: The suite includes classic fragment-style payloads (Categories 1-3)
# which the SELECT-prefix rule rejects, alongside statement-level attacks (Categories 4-8)
# representative of the POST /query interface's threat model, where the caller submits a
# complete SQL statement rather than a fragment interpolated into a surrounding query.
#
# Format: one payload per line; lines starting with # are comments;
# [BYPASS-L4] marks payloads that pass through Layer 4 and are stopped by Layer 1.
